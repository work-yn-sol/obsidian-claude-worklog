# Obsidian + Claude Code 업무 관리

AI가 다음 날에도 이어서 일하게 하는 업무 기록 구조.

- `vault-template/`은 바로 쓸 수 있는 볼트 틀이다. 내용은 비어 있다.
- `examples/`는 채운 모습을 보여 주는 가상 예시다(프로젝트 하나, 일지 하나).
- 시작하는 법은 맨 아래 [시작하기](#시작하기).
- 확인한 환경: Windows + WSL(Ubuntu)에서 Claude Code를 쓰는 경우만. Windows · macOS에서 Claude Code를 바로 쓰는 경우는 확인하지 않았다.

## 1. 핵심 아이디어

Claude는 세션이 끝나면 대화를 기억하지 못한다. 업무 상태를 파일로 남기고, 새 세션이 그 파일을 읽고 이어서 일하게 한다.

- 사람과 AI가 같은 기록을 본다. 사람은 Obsidian으로 열고, Claude는 같은 폴더를 파일로 읽고 쓴다.
- 판단과 결정은 사람이 한다. Claude는 기록 초안과 근거 찾기를 맡는다.

## 2. 전체 그림

```
 [Obsidian 업무 볼트]  ← 사람이 보고 메모
        │  같은 폴더
        ▼
 [Claude Code]  볼트 폴더에서 연다. 볼트 CLAUDE.md가 자동으로 읽힘
        │
        └─ 일지 · 할 일 · 결정 기록을 볼트에 쓰고 git 커밋

 (선택) 코드 작업 저장소에서 일할 때:
   저장소 CLAUDE.md가 볼트의 지금.md · 할일.md를 불러옴(@import)

 받은 자료 원본: 볼트 밖 자료 폴더 (볼트에는 링크만)
```

## 3. 폴더 구조

| 위치 | 내용 | 규칙 |
|---|---|---|
| `CLAUDE.md` | 볼트 길잡이(60줄 안팎) | 어디를 읽을지만 적고, 절차는 각 폴더에 둠 |
| `현황.md` | 진행 중 프로젝트 목록 | 프로젝트마다 한 줄 |
| `일지/To_Process/` → `Processed/` | 하루 한 파일 | 주간 보고에 반영하면 `Processed/`로 옮김 |
| `주간/` | 주 한 파일 | 금요일에 그 주 일지를 묶어 작성 |
| `프로젝트/과제번호_이름/` | 과제별 폴더 | 아래 표 |
| `센터/`, `회사/` | 마감 기한 없는 부서 업무, 회사 공통 정보 | 원본은 볼트 밖, 여기에는 링크만 |
| `보관/` | 끝난 프로젝트, 마감이 있던 센터 · 회사 업무 | 지우지 않고 원래 경로째 옮김 |
| `Templates/` | 양식 6개(일지 · 주간 · 카드 · 과업 · 회의 · 결정) | Obsidian 템플릿 플러그인이 씀 |

프로젝트 폴더 안:

| 파일 · 폴더 | 내용 |
|---|---|
| `_카드.md` | 기간, 사람, 내 범위, 마일스톤, 작업 위치, 보고 규칙 |
| `지금.md` | 하는 중 · 미결만(20줄 안팎). 퇴근 전에 덮어씀 |
| `할일.md` | 할 일 원본. 할 일은 여기에만 씀 |
| `자료.md` | 받은 자료 원본 링크 |
| `WBS/` | 과업 하나에 파일 하나. 상태 · 진척률 · 산출물(리비전) |
| `회의/`, `결정/` | 회의 하나, 결정 하나에 파일 하나. `YYYY-MM-DD 요지.md` |

모든 폴더에 `_여기는.md`가 있고, 그 폴더에서 지킬 절차를 적어 둔다. Claude는 일을 시작하기 전에 해당 폴더의 이 파일을 읽는다.

## 4. 연결 방식

- 기본: 볼트 폴더에서 `claude`를 연다. 볼트 `CLAUDE.md`가 읽히고, "오늘 할 일 없어?"라고 하면 진행 중 프로젝트의 `지금.md` · `할일.md`를 읽고 답한다.
- 같은 폴더: Obsidian과 Claude Code가 같은 볼트 폴더를 연다. 사람이 Obsidian에서 고친 내용을 Claude가 바로 본다.
- 선택: 코드 작업 저장소에서 Claude Code를 쓰면, 그 저장소 `CLAUDE.md`에 `@<볼트>/프로젝트/<과제>/지금.md`와 `할일.md`를 적어 둔다. 세션을 열 때 두 파일이 자동으로 읽힌다.
  - Windows는 `@~/…`처럼 `~/`로 시작한다. WSL은 같은 폴더를 `/mnt/c/…`로 본다.
  - 볼트가 저장소 밖이라 첫 세션에 외부 파일 불러오기 승인 창이 뜬다. 허용한다.
- 이력: Claude가 기록을 고치면 작업 단위로 git 커밋한다.

## 5. 한 정보는 한 곳에만

같은 내용이 여러 곳에 있으면 어느 쪽이 맞는지 모르게 된다. 기록 종류마다 둘 곳을 하나로 정했다.

| 정보 | 둘 곳 | 다른 곳에서는 |
|---|---|---|
| 할 일 | `할일.md` | 일지 '오늘 할 일', `지금.md`가 여기서 가져감 |
| 지금 상태 | `지금.md` | 덮어쓰고, 지난 판은 git |
| 결정 | `결정/` 파일 | 누가 · 언제 · 무엇 · 근거 · 영향 |
| 과업 진척 | `WBS/` 파일 | 금요일 WBS 입력값과 같게 둠 |
| 한 일 | 일지 '한 일' | 주간 보고가 모아 감 |

## 6. 하루 흐름

| 때 | 사람 | Claude |
|---|---|---|
| 출근 | Obsidian에서 오늘 일지 열기 | (전날 채워 둔) '오늘 할 일'이 이미 있음 |
| 작업 시작 | Claude Code를 열고 "오늘 할 일 없어?" | `지금.md` · `할일.md`를 읽고 우선순위 제안 |
| 작업 중 | 결정 | 할 일 갱신, 결정 노트 초안, 근거(리비전 · 경로) 붙임 |
| 퇴근 전 | "일지 써줘" | ① 오늘 '한 일' ② 다음 근무일 '오늘 할 일'(마감 지난 것 → 그날 마감 → 나머지) ③ `지금.md` 덮어쓰기 |
| 금요일 | "주간 보고 써줘" | 그 주 일지를 묶어 주간 보고, WBS 입력값 정리, 끝난 할 일 지움 |

일지 '한 일'은 Claude가 쓰고, '메모'는 사람이 쓴다. Claude는 메모를 고치지 않는다.

## 7. 규칙과 이유

`CLAUDE.md` 3절 "항상 참인 규칙"과 그 이유.

| 규칙 | 이유 |
|---|---|
| 수치 · 목록은 실측한다. 문서의 수치는 낡은 것으로 본다 | AI가 오래된 문서 수치를 그대로 옮기는 일이 잦음 |
| 문서와 실물(저장소 · 코드)이 다르면 실물이 맞다. 임의로 맞추지 않고 보고한다 | AI가 조용히 한쪽을 고쳐 버리는 것을 막음 |
| 기록에는 출처를 붙인다. 없으면 "출처 미확인" | 나중에 근거를 다시 찾지 않게 |
| 결정은 사람이 한다. Claude는 제안까지 | 책임 소재를 분명히 함 |
| 같은 실수를 두 번 하면 규칙 한 줄을 더한다 | 규칙이 경험으로 자람 |
| 상주 자동화 · 훅 · 스킬은 만들지 않는다. 같은 요청이 세 번째일 때 검토 | 구조가 복잡해지는 것을 막음 |

하지 않는 것(5절): 개인 문서 폴더는 열지 않는다. 파일 이름에 `대외비` · `비밀값`이 있으면 읽지 않는다. 원본 자료는 복사하거나 고치지 않는다.

## 시작하기

준비: Obsidian, Claude Code, git. Windows에서 WSL 없이 쓰면 Git for Windows를 설치한다.

1. 이 저장소를 받는다: `git clone https://github.com/work-yn-sol/obsidian-claude-worklog`
2. 그 폴더에서 `claude`를 열고 "START.md대로 볼트 세팅해줘"라고 한다.
3. Obsidian에서 새 볼트 폴더를 열고, 커뮤니티 플러그인 `Calendar` · `Periodic Notes`를 설치해 켠다. 설정값은 `.obsidian/plugins/*/data.json`에 이미 들어 있다.
4. 이후에는 볼트 폴더에서 `claude`를 열고 "오늘 할 일 없어?"로 시작한다.

손으로 하려면 `vault-template/`을 원하는 곳에 복사하고 `START.md` 3~5단계를 직접 한다.
